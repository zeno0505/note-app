# DAG 접두사별 요약

처음에는 `T`를 선택한다. 실제 ID의 `접두사-숫자[문자 접미사]` 형식에서 접두사를 추출한다. `T-227`, `MP-002c`, 숫자 하위 작업 `T-019a-1`을 지원하며 `T`와 `TT`는 다른 범위이다. 형식 미지원 ID의 개수도 별도로 표시한다. `T`가 없으면 빈 선택 범위를 유지하고 AI 버튼을 막는다. 다른 실제 접두사를 사용자가 직접 선택해야 한다.

선택은 앱 소유 프로젝트 등록 파일의 선택적 `summaryPrefix` 필드에 저장한다. 노트 원본, 링크, 읽기 허용 목록은 수정하지 않는다. 같은 DAG의 재연결과 프로세스 재시작에서도 명시한 선택을 복원한다. 다른 DAG는 자신의 선택 또는 초기 `T`를 사용한다.

전체 검증된 read model에서 접두사를 먼저 필터링한다. 화면과 규칙 설명은 그 결과의 원문 순서에서 200개를 표시하고, 작업 이름은 문장당 5개까지 설명한다. 수동 AI의 작업 입력은 전체 선택 범위에서 상태 우선순위(진행, 차단, 검토, 의존성 완료 선언, 기타 미완료, 완료)와 같은 상태의 ID 문자열 순서로 최대 20개를 선별한다. 따라서 표시 상한 뒤의 진행 작업도 AI 선별 대상이다. ID 번호나 원문 위치를 최신 작업 시각으로 해석하지 않는다. 작업별 갱신 시각이 없는 자료에는 최신 작업이라는 표현을 사용하지 않는다. 입력 바이트 상한을 넘으면 호출 전에 중단한다.

다른 접두사의 작업 본문은 포함하지 않는다. 선택 작업이 연결하는 다른 접두사의 내부 의존성은 ID·내부 구분·선언 상태만, 외부 의존성은 ID·외부 구분·상태 미확인만 남긴다. 규칙 문장은 의존성 메타데이터 8개를 표시하고 나머지 개수를 알린다. 외부 의존성 충족이나 실제 구현·테스트·배포 완료를 추정하지 않는다.

접두사와 작업의 대응이 명시되지 않은 프로젝트 문서, 등록 발췌문, 프로젝트 전체 PR·CI 본문은 현재 접두사 요약 입력에서 제외한다. 기존 문서 등록과 이전 기록을 삭제하지 않는다. 작업과 연결된 별도의 실제 검수 근거를 결합하는 작업은 이후 범위이다.

규칙 캐시는 워크스트림·DAG·접두사로 구분한다. AI 저장 키는 호스트·정규 DAG 경로·`prefix-v1`·접두사로 만든다. 성공 본문, 실패 예약, 진단 재시도 예약, 입력 해시는 이 저장 키를 사용한다. 선택 작업과 연결 의존성으로 만든 근거 해시에는 다른 접두사의 무관한 본문을 넣지 않는다. 전환하면 동의 체크박스와 현재 UI 실행 상태를 초기화하고 진행 중인 요청을 취소한다. 늦은 결과는 재검증을 통과하지 못하면 저장하지 않는다.

기존 전역 AI 저장 파일과 실패 예약은 그대로 보존하며 현재 선택의 결과로 읽지 않는다. 이전 프로젝트 전체 규칙 이력과 6관점 후보·승인 기록은 이전 기록으로 표시하며 현재 접두사의 검증 근거로 승격하지 않는다. 6관점 이력은 읽기 전용으로 유지한다. 프로세스 재시작 뒤 이미 저장된 접두사 결과도 새 입력과 재검증되기 전에는 역사적 결과로 표시한다. 화면 조회나 접두사 전환은 모델을 호출하지 않는다.

## 검증

- `npm run check`: 타입 검사, 전체 단위 테스트, 빌드.
- `npm run test:electron:prefix`: 격리된 가상 DAG와 실제 host/preload/renderer에서 기본 T, 정확한 전환, 200개 상한 뒤의 작업, T 부재, 동의 초기화, 재연결, 재시작, 밝은/어두운 Select 화면을 검증한다. 모델 실행을 차단하며 사용자 자료를 사용하지 않는다.
- `project-model.test.ts`: 접두사별 입력/캐시/실패 예약 분리, 이전 결과 보존, 취소와 늦은 합성 응답의 저장 차단을 검증한다. 모델 어댑터는 합성이다.

이 검증은 실제 모델의 한국어 요약 내용 수용이나 Phase 1 전체 완료를 증명하지 않는다. 실제 모델 호출·main 병합·배포는 이 변경의 검증에 포함하지 않는다.
