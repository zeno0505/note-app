# Phase 2 기존 계획 이력과 화면 기반 재설계

**현재 등록 계획:** [T-036~T-048 화면 기반 설계·태스크 관계](phase2-task-design-2026-10-07.md). 사용자 v7 화면 수용 및 후속 공통 상태 Select 결정에 따라 planning/pending 13개를 추가했다. 기존 T-029~032는 아래 이력과 제외·대체/보류 관계를 보존한다. 제품 구현과 모델 호출은 시작하지 않는다.

아래는 2026-10-06 사용자 승인에 따른 범위 구체화 이력이다. 관련 로컬 DAG의 T-029~T-032는 planning/pending이며, 이 문서로 구현·모델 파견·자동 DAG 쓰기를 시작하지 않는다. 기존 Phase 1 수용기준도 대체하지 않는다.

**2026-10-07 KST 후속 합의:** 실행은 Orca가 담당하고 note-app은 관측·리뷰·파견 보류 권고에 집중한다. 아래 표는 기존 계획 이력이다. T-029의 실행 허가/강제 제어와 T-030의 직접 개발 위임은 새 범위에서 제외·대체된다. [방향 합의와 남은 논의](phase2-discussion-needed-2026-10-07.md#이후-사용자-합의--실행은-orca-note-app은-관측리뷰권고)를 기준으로 후속 계획을 정리하며 구현에 착수하지 않는다. 프로젝트별 Orca 화면 전환은 지원 여부 확인 후 가능한 경우만 포함한다.

**후속 순서 합의:** 별도 제작 중인 가벼운 HTML 프로토타입을 먼저 보고 화면·렌더링·라이브러리를 논의한 뒤, 그 화면에 맞춰 DAG 태스크를 설계한다. 이후 화면을 수용하고 T-036~048로 재분해했다. 아래 표는 기존 개념 계획 이력이며 현재 확정 구현 목록으로 사용하지 않는다. [순서와 구조 조사 한계](phase2-discussion-needed-2026-10-07.md)를 함께 참고한다.

| 태스크 | 계획 결과물 | 후속 결정 |
| --- | --- | --- |
| T-029 쿼터·메모리 실행 정책 | 실제 관측 freshness, unknown, 메모리 여유/압력, 실행 대기·회복과 동시 실행 수의 설계 및 측정 계획 | 측정 후 임계치, 제공자/전송 정책, 호출 상한 |
| T-030 근거 있는 개발 위임 | 목표·범위·수용기준 → 실행 계획 → 작업 결과 → 검증 근거 → 사용자 검토의 계약 | 허용 저장소/작업, 파견·취소·재시도 승인 경계 |
| T-031 DAG 갱신 제안 | source hash에 묶인 변경 preview, no-op/stale 차단, 승인과 감사 기록의 설계 | 누가 어떤 변경을 승인하는지; 자동 done/merge는 별도 결정 |
| T-032 트레이 popover·최근 3개 | 최근 프로젝트의 정의·정보 우선순위·클릭 흐름 시안 | 최근의 의미, 완료 프로젝트 포함, 빠른 작업의 허용 범위 |

T-029는 현재 CodeBurn 관측과 순수 `chooseAgent` 추천을 출발점으로 사용하되, 추천을 실행 허가로 바꾸지 않는다. 관측 실패나 오래된 quota는 0 또는 실행 가능이 아니다. 사용자 프로세스를 종료하지 않으며 지금 임의 임계치를 확정하지 않는다.

T-030은 CI 성공만으로 작업 완료를 인정하지 않는다. 변경 범위, 실제 검증 명령/환경/결과, 실패·미검증과 사용자 결정이 필요한 항목을 제시하는 제품 흐름을 설계한다. 실제 에이전트 송신은 이 계획 범위 밖이다.

T-031은 기존 DAG read-model과 안전한 쓰기 도구 계약을 검토한다. 수용기준·의존성을 무시한 done, 사용자 승인 없는 원문 수정, PR 병합을 자동화하지 않는다. 입력이 바뀌면 기존 승인과 preview는 무효가 된다.

T-032는 현재 트레이 클릭으로 창을 여는 동작을 기반으로 한다. 최근 3개를 위해 사용자 행동을 추가 추적할지 먼저 결정하고, unknown/stale/완료 상태를 실제 관측과 구분한다.

일반 프로젝트 AI의 첫 대상·허용 자료·제공자·수동 실행 정책은 [별도 결정안](project-model-reading-integration.md)에 있다. 이 네 계획 태스크와 private 자료 전송 승인은 별개다.

## T-029

자원 관측·분배의 추가 제안은 [2026-10-07 논의 필요 문서](phase2-discussion-needed-2026-10-07.md#1-병렬-에이전트의-유한-자원-분배)에 기록했다. planning/pending과 실행 승인 경계는 유지한다.

## T-030

직접 개발 위임은 후속 합의에서 제외·대체됐다. 기존 계획을 삭제하거나 완료 처리하지 않는다. 자가 검증과 수동 태스크 요약의 근거·리뷰 계약은 [태스크 단위 요약 논의](phase2-discussion-needed-2026-10-07.md#3-태스크-단위-요약과-검수-근거)로 별도 논의한다.

## T-031

읽기 전용 그래프/필터를 기존 변경 제안·승인과 분리할지는 [DAG 시각화 논의](phase2-discussion-needed-2026-10-07.md#2-큰-dag의-읽기와-필터)에서 결정한다.

## T-032

최근 프로젝트 진입과 자원/태스크 검토 UX의 관계는 [기존 계획과의 관계](phase2-discussion-needed-2026-10-07.md#기존-phase-2-계획과의-관계)에 기록했다. 구현 상태를 변경하지 않는다.
