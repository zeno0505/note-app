# 프로젝트별 AI 읽기 요약 연결 — 결정안

상태: 공개 note-app 수동 선행 실험 승인·연결 구현 진행. 일반 프로젝트와 자동 실행은 후속 평가·결정 대기다.
2026-10-06 사용자는 공개 note-app의 선별 근거만 기존 로그인 Claude 구독 인증으로 전송하는 수동 실행을 승인했다. 동시 실행 1, 입력당 생성 1회·완료 응답 검증 실패 수정 최대 1회, 동일 입력 재호출 0, 최신 성공 본문 1개와 실패 시 이전 결과/낡음 표시를 유지한다. 별도 API 과금이나 자격증명 생성은 없다. 결과의 한국어 네 섹션을 사용자가 평가한 뒤 다른 note 프로젝트로 점진 적용하며 이번 승인으로 일괄 호출하지 않는다.

## 재사용할 기반과 아직 연결하지 않은 부분

- 현재 규칙 기반 reading scheduler는 프로젝트의 근거 fingerprint 변화와 no-op를 감지한다. 일반 “지금 요약”은 전체 설정 소스의 읽기·규칙 설명 갱신이며 AI 실행이 아니다.
- 공개 하네스는 단일 실행 슬롯, 입력 hash 예약, 생성 1회·검증 실패 수정 1회 상한, 중단/늦은 응답 차단을 제공한다. 입력 계약은 공개 note-app 한 프로젝트로 제한되어 있어 개인 자료를 그대로 넣는 식으로 확장하지 않는다.
- 모델 저장 기반은 프로젝트별 최신 성공 본문 하나와 최소 호출 방지 ledger를 원자적으로 저장한다. 실패/취소는 이전 성공본을 보존하고 stale 표시한다. 현재 앱 IPC는 공개 note-app 결과 읽기만 연결한다.
- `chooseAgent`는 테스트된 순수 추천 함수다. CodeBurn 관측과 일반 모델 실행에 연결되어 있지 않다. 미확인 quota는 0 또는 실행 허가로 해석하지 않는다.

## 제안하는 연결 순서

1. 사용자가 첫 프로젝트와 읽기·모델 전송이 허용되는 자료를 정한다. OS 읽기 허용 목록과 외부 모델 전송 승인은 별개다.
2. main 측에서 확인된 프로젝트 identity와 정규 경로를 사용해 제한된 근거 팩을 준비한다. 등록된 문서와 선택한 DAG task slice만 대상으로 하고 inbox·전체 vault·무관한 프로젝트·대화본문·자격증명은 자동 포함하지 않는다. 입력 크기/출처/변경 hash를 먼저 검토 가능하게 한다.
3. 별도 일반 프로젝트 입력 schema와 승인 token을 추가한다. 공개 실험의 literal 프로젝트 제한을 제거해 우회하는 방식은 쓰지 않는다. 계획 hash·출처 hash가 바뀌거나 읽기 허용이 철회되면 기존 실행 승인은 무효다.
4. 공개 note-app 첫 실행은 수동 버튼, 전역 동시 실행 1, 입력당 생성 1회·완료 응답 검증 실패 수정 최대 1회로 제한한다. timeout/불확실 제출은 자동 재전송하지 않는다. 이 정책을 일반 프로젝트나 자동 실행 승인으로 확대하지 않는다.
5. 선택된 제공자의 정상 구독 CLI, 도구/MCP/추가 탐색 차단, 소유 프로세스 종료, quota 관측의 freshness를 검증한 뒤 최신 저장소에 게시한다. 비용/토큰 관측을 구독 실제 청구액으로 단정하지 않는다. Codex는 동일한 읽기/도구 경계가 입증되기 전 자동 대체하지 않는다.
6. 앱의 선택 상세에서 규칙 설명과 AI 최신 성공본을 구분한다. 입력 hash·생성 시각·provider·검증 상태와 stale를 표시한다. 준비/실행/취소 API는 trusted owner와 명시적 계획 승인에 묶는다. 자동 갱신 정책은 그 뒤 별도 결정한다.

## 이번 선행 실험과 남은 결정

- 이번 대상은 공개 note-app 한 개의 선별 공개 근거이며 기존 Claude 구독으로 수동 실행한다. 항목별 공개 출처/줄/hash를 확인하고 입력 목록을 기록한다.
- 실제 출력은 필수 항목 누락, 구현/계획/미확인, 논의 필요/설계 완료, 날짜/SHA/검증 근거, 근거 없는 주장과 가독성을 검토한다. 기계 스키마 통과와 내용 정확성을 구분한다.
- 다른 프로젝트의 자료 범위·제공자·자동 실행 정책은 이번 출력의 사용자 평가 후 별도 결정한다. 신규 자격증명은 필요 조건으로 가정하지 않는다.

private 자료 전송·일반 자동 모델·새 자격증명/보안 변경은 이번 범위 밖이다. Phase 2의 자동 병렬 파견과 메모리/쿼터 기반 scheduler도 별도 범위다.
