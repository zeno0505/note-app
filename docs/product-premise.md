# note-app 제품 대전제

기록일: 2026-10-09

## 확정된 제품 목적

note-app은 agent-skills/dag-stack이 다루는 요구사항 분석, 태스크 설계, 개발, 검수의 맥락과 근거, 진행 상황을 개발자가 시각적으로 이해하고 검수하는 도구다. 개발자가 에이전트가 작성한 코드와 산출물을 파악할 때 드는 인지 부담을 줄이는 것이 제품의 중심 목적이다.

이 대전제와 아래 역할 구분은 사용자가 명시한 제품 방향이다. 화면 배치, 탐색 방식, 지원 문법, 성능 수치 등 세부 사항은 [Phase4 설계 권장안](phase4-document-review.md)에서 별도로 다룬다. 2026-10-09 후속 확인에서 검토한 목업과 아래 초기 범위의 Phase4 구현은 승인되었다. 구현 승인은 배포·릴리스·설치본 교체 승인이 아니다.

## 누가 무엇을 하는가

- 일반적으로 관측 대상 프로젝트의 개발 실행은 Orca가 담당한다. note-app은 해당 작업의 맥락, 선언, 관측 결과와 검수 근거를 읽기 쉬운 형태로 연결한다
- note-app 자체의 개발 담당은 dot이다. 이 제품을 개발하는 일을 Orca로 이관한다는 뜻이 아니다
- agent-skills/dag-stack은 요구사항 수집부터 계획, 작업 전달, 리뷰와 변경 추적까지 이어지는 문서와 DAG의 업무 계약을 제공한다
- 최종적으로 무엇이 요구되었고 실제로 검증되었는지 판단하는 주체는 개발자다. 앱은 근거를 제시하며, 문서의 존재를 검증 통과로 바꾸지 않는다

## 사용자가 앱 안에서 답할 수 있어야 하는 질문

1. 이 프로젝트는 어떤 요구사항과 제약에서 시작했는가
2. 이 태스크가 필요한 이유와 수용 기준은 무엇인가
3. 다른 태스크와 어떤 순서와 의존 관계를 가지는가
4. 구현과 리뷰에 어떤 문서가 연결되어 있는가
5. 완료 선언의 근거는 무엇이며 아직 확인하지 못한 부분은 무엇인가
6. 검토를 시작한 뒤 요구사항, DAG 또는 문서가 바뀌었는가

이를 위해 원문 상태, 정책에 따른 해석, 실제 관측, 검증 결과를 구별한다. 최신성이나 읽기 범위를 확인할 수 없으면 그 한계를 함께 표시한다. 연결되지 않음, 읽지 못함, 기록 없음, 지원하지 않음을 모두 같은 빈 화면으로 표현하지 않는다.

## Phase4의 확정 범위

- 그래프 또는 태스크 목록에서 태스크를 선택하면 우측 상세 하단에서 관련 wikilink Markdown 문서를 앱 안에서 열람한다
- 태스크를 선택하지 않아도 프로젝트 수준에서 Markdown 파일을 찾아 읽을 수 있는 문서 탐색 섹션을 제공한다
- VSCode나 Obsidian을 다시 열지 않고 요구사항, 설계, 구현 기록과 검수 맥락을 이어서 확인할 수 있게 한다
- 프로젝트 노트 루트와 별도로 명시 연결한 소스 문서·검수 폴더만 탐색한다. 전체 볼트나 저장소를 자동 검색하지 않는다
- Markdown과 제한된 안전 Mermaid, PNG 열람, 읽기 전용 YAML/JSON 원문을 지원한다. 큰 문서도 조용히 잘리지 않아야 한다
- 상대 링크·wikilink·heading은 누락·모호함·범위 밖·미지원 상태를 구분한다
- Phase4를 위한 별도 개발 실행 UI는 만들지 않는다

기존 실행 연계 기능이나 수동 AI 요약을 제거하라는 요구는 아니다. 다만 문서를 읽는 동작이 실행, 모델 호출, 노트 쓰기 또는 외부 앱 열기를 암묵적으로 일으켜서는 안 된다.

## 제품 판단 원칙

### 맥락을 잃지 않는 검수

문서를 읽었다가 돌아와도 선택한 프로젝트와 태스크, 목록 필터, 페이지와 위치를 유지해야 한다. 관련 문서를 따라 이동할 때 출발 태스크와 문서의 관계가 보여야 한다. 긴 문서를 읽기 위해 넓혀도 원래 검수 위치로 돌아올 수 있어야 한다.

### 출처를 좁고 정확하게 연결

명시된 링크와 검증된 프로젝트 경로를 사용한다. 같은 파일명이나 비슷한 태스크 ID라는 이유만으로 관계를 확정하지 않는다. 계약에 따른 예상 위치에서 발견한 파일과 DAG가 직접 연결한 문서는 구분한다. 파일 이름, 문서 내용, 완료 상태를 서로 대신하는 근거로 사용하지 않는다.

### 원문과 최신성 보존

출처 파일, 관측 시점, 내용 해시와 표시 한계를 확인할 수 있어야 한다. 문서가 바뀌면 검토 중인 내용이 조용히 교체되지 않아야 한다. 읽기 실패나 조회 불가는 “변경 없음” 또는 “검증 완료”를 뜻하지 않는다.

### 읽기 권한과 실행 권한 분리

허용된 프로젝트 범위의 문서만 읽는다. 볼트 읽기 허용을 전체 볼트 탐색 권한으로 확대하지 않는다. 경로 탈출, 임의 파일 접근, 원격 이미지 요청, 문서 안의 스크립트나 명령 실행은 막는다. 안전한 렌더링을 위해 일부 Markdown 문법을 지원하지 않을 수 있으며 이때 원문과 이유를 보여 준다.

### 기존 기반을 확장

현재 제품의 태스크·DAG, 프로젝트 작업공간, 근거 파일 읽기와 안전한 Markdown 렌더링을 우선 재사용한다. Phase4는 이 기반을 검수 흐름에 맞게 연결하는 단계다. 새로운 편집기나 실행 오케스트레이터를 만드는 단계가 아니다.

## Phase4 비목표

- Markdown 편집, 생성, 저장, 자동 가져오기 또는 문서 동기화
- 태스크 실행, 에이전트 파견, 모델 호출, 실행 터미널의 신설
- 문서 열람에 따른 태스크 상태 변경, 리뷰 승인, 자동 완료 처리
- Obsidian 플러그인, Dataview, HTML, Slidev 또는 Mermaid 내부 코드·명령 등 실행 가능한 콘텐츠의 실행. Mermaid는 실행 없는 제한된 도형·텍스트 표시만 지원한다
- 전용 PDF·CSV·SQL 편집기
- 전체 볼트 검색, 타 프로젝트 문서의 자동 연결, 관련 없는 파일의 수집
- 코드 변경 전체를 대신 검토하거나 파일 존재만으로 테스트 결과를 판정하는 기능

## 근거와 갱신 기준

이 문서는 2026-10-09 사용자의 명시적 제품 방향과 역할 정정을 기록한다. 후속 설계가 이 대전제를 바꾸려면 변경 이유와 영향을 먼저 검토한다. 외부 skill의 명칭이나 경로 계약이 바뀌어도 제품 목적과 개발 담당을 자동으로 바꾸지 않는다.

현재 코드에서 확인한 기반과 최신 공개 dag-stack 문서 계약, 남은 호환성 차이는 [Phase4 설계](phase4-document-review.md)에 구분해서 기록했다.
