# 재연결 후 조회 준비와 안전한 reader 복구

재연결 확인은 노트 링크와 선택 DAG의 저장을 뜻한다. 그것만으로 AI 요약 준비를 성공으로 표시하지 않는다. 확인 응답의 `readiness`는 같은 시점의 연결, 최신성, 정확한 선택 DAG의 `ready`, 프로젝트의 `sourceState=available`, 모델 실행 경로 설정을 별도로 검사한다. 전송 동의는 이후 사용자 화면에서 확인하며 모델 호출은 자동으로 하지 않는다.

기존 문제는 취소·timeout의 즉시 응답 뒤 reader가 영구 폐기되던 상태와, 파일 연결 성공만 검사하던 인수조건의 조합이었다. 이전 재연결 Electron 테스트는 링크/백업/선택 저장/재시작 매핑을 확인했지만 실제 DAG 조회와 AI 버튼 활성화를 확인하지 않았다. 테마 검사 또한 기능 인수검사를 대신하지 않는다.

## 복구 경계

- `cause`는 최초 중단의 `cancelled`, `timeout`, 실제 `cleanup_unverified`를 구분한다.
- 응답 완료와 정리 완료는 다르다. 파일 I/O, 핸들 닫기, 소유 query 그룹 정리 및 임시 스냅샷 제거가 끝나기 전에는 `cleanup=pending`이고 복구를 거부한다.
- 프로세스 그룹 정리나 핸들 닫기가 확인되지 않으면 `cleanup=unverified`로 계속 차단한다. 동일 reader의 재사용이나 무조건적인 새 reader 생성으로 우회하지 않는다.
- `cleanup=verified`인 폐기 reader만 수동 새로고침에서 새로운 query 세대로 전환한다. 캐시를 비우고 현재 원본을 다시 해시·조회한다. 늦은 이전 응답은 게시하지 않는다. 동시에 진행 중인 조회는 복구할 수 없다.
- 동일 정식 DAG 경로와 허용 범위를 유지한다. 사용자 노트, 권한, 모델 ledger와 저장된 모델 요약은 복구 대상으로 수정하지 않는다.

## 요청별 인수조건과 근거

| 요청 | 검증 |
| --- | --- |
| 디렉토리 선택 → 재연결 확인 | 실제 Electron/IPC/main, 격리된 Git worktree와 실제 pinned query; 원본/기존 링크 백업 보존 |
| 재연결 → DAG 조회 준비 | 저장된 정확한 비표준 DAG를 조회하여 `ready`, `sourceState=available`, 최신 연결 확인 |
| 요약 준비 → 버튼 활성 | 동의 전 비활성, 동의 후 활성 확인; 모델 spawn 차단 및 호출 수 0 |
| 반복·취소·재시작 | 같은 링크 확인으로 백업이 늘지 않음; 취소 보존; 재시작 후 같은 DAG 선택 유지 |
| reader 취소·동시 조회 | 중복 조회 `busy`; 응답 뒤 정리 대기; 검증된 정리 후 반복 세대 복구 |
| timeout·정리 실패 | 미해결 파일 I/O 동안 복구 거부; 실제 소유 그룹 정리 실패 주입 시 영구 차단 |
| 현재 Mac 설치본 | 정식 앱의 source SHA/서명/설정 확인 후 정확히 등록된 대상의 디렉토리 선택, 같은 링크·DAG 확인, `ready`/`available`/동의 후 버튼 활성까지 캡처한다. 모델 실행 버튼은 누르지 않는다. 설치 후 별도 인수 결과로 판정한다. |

자동 회귀: `npm run check`, 승인된 외부 query 환경의 `npm run test:electron:reconnect`. 실제 Mac의 설치·종단·보존 증거는 저장소 밖의 비공개 `button-diagnosis` 실행 산출물에 보관한다. 이 문서 작성 시 설치 후 실제 대상 검증은 아직 진행 전이며, 코드 검사만으로 완료를 선언하지 않는다.
