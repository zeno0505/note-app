# Phase 2: 제한된 Markdown 근거 보기

## 목적과 범위

`SafeMarkdown.vue`는 이미 메인 프로세스에서 읽기 권한과 파일 크기를 확인한 문서 문자열을 표시한다. HTML을 생성한 다음 정화하는 방식이 아니라, 작은 Markdown 구문 트리를 만들고 Vue의 텍스트 자식으로 렌더링한다. 파일 존재, 연결 표시, 이미지 표시 여부는 테스트 통과나 설계 검증을 뜻하지 않는다.

이 구현은 CommonMark 전체 파서가 아니다. 추가 라이브러리를 설치하지 않는 명시적인 부분집합이다. 기존 계획의 markdown-it·DOMPurify 후보를 채택했다고 주장하지 않는다. 지원 범위를 넓힐 때에도 현재의 파일 읽기 권한, 무네트워크 원칙과 자원 제한을 유지해야 한다.

지원하는 서식:

- `#`부터 `######`까지의 ATX 제목, 빈 줄로 구분하는 문단, 문단 내부 줄바꿈
- 백틱 또는 물결표 3~64개로 여는 코드 울타리와 짧은 인라인 코드
- 한 줄짜리 항목으로 이루어진 단일 단계 글머리·번호 목록
- 최대 4단계 인용문, 제한된 `*강조*`·`**강조**`·밑줄 강조
- `[이름](문서.md#앵커)`, 공백을 포함하는 `<대상 경로>`, 선택적인 따옴표 제목
- `[[문서#앵커|별칭]]`, `![이름](그림.png)`, `![[그림.png|별칭]]`
- 같은 문서의 `#앵커`로 이동

표, Setext 제목, 참조식 링크, 각주, 수식, HTML 렌더링, 자동 링크, 중첩·여러 문단 목록, CommonMark 전체 구분자 규칙은 지원하지 않는다. 인식하지 못한 구문은 일반 문자열로 남는다. 매우 긴 문단이나 깊은 중첩도 문자열로 표시하고 제한 안내를 보인다. 링크 이름 안의 서식은 해석하지 않는다. 불완전한 코드 울타리는 문서 끝까지 코드로 표시한다.

## 보안 경계

- 소스 문자열은 Vue 텍스트 자식이나 일반 문자열 속성으로만 전달한다. `v-html`, HTML 삽입, DOM 파서, 사용자 지정 태그, 이벤트 속성 생성, 스크립트 실행을 사용하지 않는다
- `<script>`, `<img>`, `<svg>` 등 HTML 문자열은 화면에 글자로 남는다
- 문서 링크는 `href`가 없는 버튼이다. 이미지도 `src`가 없는 버튼·자리표시자다. 링크 분석이나 화면 표시로 네트워크 요청이 발생하지 않는다
- 외부 URL, URI 스킴, 절대 경로, 상위 경로, 역슬래시, 퍼센트 인코딩, 쿼리 등은 비활성 버튼과 한국어 사유로 표시한다
- 로컬 이미지 형식은 PNG·JPEG·GIF·WebP, 로컬 문서는 근거 리더가 지원하는 텍스트 확장자로 제한한다. 실제 내용 검증은 메인 리더의 책임이다
- 구문상 로컬 연결이라는 판정은 읽기 권한을 부여하지 않는다. 별도 허용 루트, 등록, 파일 동일성·해시, 크기와 형식 검증이 계속 필요하다
- 렌더러 번들은 Node 전용 `evidence.ts`를 가져오지 않는다. 같은 문서 앵커 이동에서도 전역 문서 선택자, 임의 선택자 조합, URL 해시 변경을 하지 않는다

## 연동 API

`src/phase2/markdown.ts`:

- `parseSafeMarkdown(text)` → `{ blocks, targets, unsupportedCount, issues, limited }`
- `extractDocumentReferences(text)` → `{ targets, unsupportedCount }`
- 대상 형식: `{ href, relativePath, anchor, label, kind: 'link' | 'image' }`
- `href`는 분석한 원래 목적지 문자열이다. 일반 Markdown의 바깥 괄호·꺾쇠·선택적 제목은 제외하고, 위키 연결의 `[[...]]`는 보존한다
- `targets`는 실제 렌더링되는 구문에서 추출한 로컬 후보만 포함한다. 코드, 비활성 연결, 같은 문서 앵커, 지원하지 않는 구문은 등록 후보가 아니다
- 동일한 `kind + href`를 중복 제거한다. 같은 파일을 다른 표기로 가리키는 링크까지 임의로 합치지 않는다
- `unsupportedCount`는 인식했지만 비활성화한 연결 수다. 전체 미지원 Markdown 구문 수나 누락 파일 수가 아니다. 분석 한도로 전체 일반 텍스트 표시로 돌아가면 등록 후보와 이 수는 모두 비워진다

`SafeMarkdown.vue`:

- 입력: `text: string`, 선택 입력 `anchor: string | null`, `disabled: boolean`
- 출력 이벤트: `open-reference`, 인자는 위 대상 형식과 동일
- 부모는 메인이 이미 발급한 현재 세션의 연결 목록에서 `href`와 `kind`를 찾아 불투명 근거 ID로 변환해야 한다. 이벤트의 `relativePath`를 IPC 파일 경로로 전달하면 안 된다
- 메인은 원문에서 직접 `extractDocumentReferences`를 호출하고 각 후보의 `href`를 `parseEvidenceTarget`으로 다시 확인해야 한다. 결과를 문서 기준 허용 루트와 기존 근거 등록 규칙으로 검증한다
- 일반 텍스트 MIME에는 기존 원문 표시를 사용하고 Markdown MIME에만 이 컴포넌트를 사용한다

## 앵커 처리

제목의 표시 텍스트를 소문자로 바꾸고 문자·숫자·결합 문자·밑줄·공백·하이픈을 남겨 로컬 앵커를 만든다. 공백은 하이픈으로 바꾸며, 충돌에는 숫자 접미사를 붙인다. 생성 규칙은 이 뷰어의 부분집합이며 다른 Markdown 제품과 같다고 가정하지 않는다.

각 컴포넌트는 자기 제목 요소만 보관한다. 일치하는 `#앵커`는 그 요소로 스크롤하고 키보드 초점을 옮긴다. 알 수 없는 앵커나 퍼센트 인코딩된 앵커는 디코딩·추측하지 않고 원문을 보존한 안내를 표시한다. 같은 문서 링크는 외부 열기 이벤트를 발생시키지 않는다. 닫힌 컴포넌트의 지연된 초기 이동은 취소된다.

## 자원 제한과 실패 표시

- 소스: UTF-8 256 KiB
- 줄 수: 8,192
- 구문 노드: 4,096
- 분석 작업 예산: 1,500,000 단위
- 문단 인라인 처리: 16,384 UTF-16 코드 단위, 최대 6단계
- 인용문: 최대 4단계
- 등록 후보: 최대 64개
- 목적지: UTF-8 4,096바이트, 이름·앵커: 각각 512바이트

소스가 크기 제한을 넘으면 일부만 정상 문서처럼 표시하지 않고 표시를 거부한다. 줄 수·노드·작업 제한에 걸리면 전체 원문을 비활성 코드 텍스트로 표시하고 안내한다. 정규식은 길이가 제한된 입력에만 사용하며, 반복 탐색에는 공유 작업 예산을 적용한다. 근거 리더의 더 엄격한 권한·자원 제한을 우회하지 않는다.

## 검증

`npx vitest run --root . tests/unit/phase2-markdown.test.ts`

단위 검증은 지원 서식, 원래 연결 문자열 보존, 메인 파서와의 후보 일치, 악성 HTML·SVG·스킴, 경로 탈출, 인코딩, 코드 안 연결 제외, 미지원 구문, UTF-8 제한, 노드·줄·작업 제한을 포함한다. Vue 서버 렌더링으로 HTML 이스케이프와 URL 속성 부재를 확인하며, 별도 호스트 렌더러로 로컬 이벤트, 비활성 버튼, 컴포넌트 사이 앵커 격리, 알 수 없는 앵커, 닫기 후 지연 이동 취소를 확인한다. Electron의 실제 창 동작과 IPC 연결은 별도 통합 검증 대상이다.
