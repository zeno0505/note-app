## Source update reliability

- Verify complete app bundles through the physical filesystem in Electron, including ASAR archive bytes and unpacked resources
- Keep the existing digest format, file identity checks, link containment and permission checks
- Use explicit readiness and joined cleanup in synthetic process tests, including delayed authentication and model startup

This patch release updates package and lockfile version metadata together. It retains the runtime fix used by the preceding private bootstrap; the release metadata and exact source commit are distinct. No dependency versions change.

An installed app containing the older ASAR validator needs a fixed, locally built bootstrap before it can prepare this source update. The planned verification sequence is bootstrap build 27 followed by release build 28. Existing release identities and the recorded release high-water mark must be preserved. Do not republish a previous build with new source, reuse one source SHA across the bootstrap and target, or bypass downgrade/identity checks.

The source release ships no personal configuration or user data. macOS packaging, signing, installation and restart acceptance must be verified on the target Mac before they are reported as complete.
