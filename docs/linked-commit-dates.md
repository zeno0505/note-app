# Linked commit dates: T-059 Linux candidate

## Implemented scope

`src/main/linked-commit-dates.ts` resolves authoritative, task-bound declarations through a main-owned adapter. It validates GitHub repository components, full SHA-1 results and strict UTC committer timestamps. Bare SHA declarations require an independently established repository scope. Exact commit/PR URLs are parsed by a restrictive grammar; credentials, ports, query strings, fragments, escapes, arbitrary hosts and schemes are rejected. Output URLs are constructed from checked repository/SHA components.

A complete commit lookup must establish unique prefix resolution. A PR lookup must establish all pages of membership and a nonempty membership revision; incomplete membership contributes no date. Conflicting records, invalid timestamps, wrong repositories and unsupported declarations remain unresolved. No author time, file mtime, source snapshot time, PR update/merge time, or repository-head fallback exists.

Counts follow the T-057 task/reference coverage contract, including unresolved references on otherwise resolved tasks and unknown declaration inspection. Duplicate declarations deduplicate only within each task. All equivalent resolved evidence is retained; maximum selection has deterministic repository/SHA/task/reference tie-breaking. Results are recursively immutable.

Budgets: 10,000 tasks, 20,000 declarations and total resolved evidence records, 1,000 commits per reference, 10-second maximum request deadline, eight cached snapshots and 16 MiB combined cache result/key bytes. Oversized inputs/outputs fail closed. Timeout/cancellation cannot publish or populate the cache with late results. Cache keys include all graph identity fields, adapter revision and declarations; `clear()` invalidates in-flight results. Transient unresolved results are not cached. The host must abort or clear on source, workspace, permission, guard, disconnect or lifecycle changes and revalidate current identity before publishing.

`src/shared/linked-date-format.ts` is a pure formatter with no I/O: exact Asia/Seoul timestamp, explicit KST suffix and a compact card date that omits the year only when matching visible year context is supplied. Different years retain full dates.

## Actual local read path

`src/main/local-linked-commit-adapter.ts` is a usable local adapter built on the existing `readGitActivityReferences` reader and `GitMetadataReadAuthority` validator. It validates authority before/within/after bounded object reads and reads `%cI` through that existing hardened reader. It does not spawn a new arbitrary command pathway, perform network calls, inspect credential material, or derive a remote identity from a local path. All bindings are main-owned. Repository-to-authorized-worktree association must already be established by the host; a filesystem grant alone is not proof of repository identity.

Local reads bypass snapshot caching because local object membership and authority may change. Repeated reads recheck the current grant and object state. PR membership is explicitly unavailable from this adapter: object existence alone does not prove PR membership.

## Production integration status

`src/main/task-graph-dates.ts` now connects the full guarded original DAG source to the local adapter through the actual registered `note-app:graph-dates` host handler and preload bridge. Repository identity comes only from the runtime's unique current-worktree match and explicitly bound joined GitHub provider identity. The host supplies current Git metadata grants. Bare references without established repository scope and missing grants remain unknown; PR references remain incomplete-membership. Unsupported declarations are counted separately, never discarded as no-reference.

The service binds the request to the current main-owned session, checks expected graph revision, re-reads/hashes the source and rechecks provider association/authority before publishing. It admits one logical read and one physical operation at a time, retaining the physical slot after cancellation until underlying source, authority, local commit or final validation work actually settles. It handles explicit cancellation and a 10-second deadline, and fails closed if the compact date response exceeds 512 KiB. The response includes global/per-task coverage and latest verified provenance plus a content-addressed metadata revision, without local paths. Full declaration/evidence lists remain main-owned. Host cancellation covers hide/blur/close, metadata-grant invalidation, read-root changes, disconnect, updater quiescence and quit. Source/session changes are revalidated before publication. Future graph UI consumers must cancel on unmount and background, compare response identity and metadata revision, and use the pure formatter; cards/tooltips are not implemented here.

No current production remote PR adapter is claimed. A future authorized remote read adapter must prove pagination completeness and membership revision, and follow the same limits. The initial local-only candidate did not recertify historical PR membership. The follow-up below records independently verified membership and a historical offline replay, without claiming production connectivity. No private task titles, relationships, paths or metadata were copied into source/tests/build.

## Verification

Focused tests use authored synthetic fixtures. They include an actual temporary local Git repository with distinct author and committer dates, exact guarded object resolution and authority revocation. They also cover reference/task coverage, missing scope, unsafe URLs, same SHA across repositories, short SHA ambiguity, incomplete/unversioned PRs, invalid timestamps, forbidden fallbacks, cache revisions, cancellation/deadline, finite bounds and KST year rollover. A synthetic IPC bus invokes the same registered production date handler against an actual temporary local Git object. This is not real Electron IPC, Mac, renderer-runtime or historical private-oracle proof.

## Bounded remote adapter and historical replay follow-up

`remote-linked-commit-adapter.ts` now implements the main-owned authorized-provider boundary. It accepts typed repository/commit/PR/page operations, never renderer endpoint URLs or credentials. It has no default network transport and reads no environment, Git credential helpers or connector tokens. The caller must retain the adapter instance so its physical-operation slot remains owned through abandoned provider calls.

The adapter enumerates at most ten 100-member pages, caps membership payloads at 1 MiB/1,000 commits, rejects duplicate/wrong-scope/page/count data, rechecks authorization and provider revision, and compares PR repository/number/head/base/count after every page. A complete result requires an explicit terminal page and exact expected membership count. A content hash binds the membership revision to the verified repository/PR state and ordered full SHA list. Strict committer timestamp validation remains in the resolver. Synthetic tests cover pagination, truncation, changed membership, scope, duplicate rows, revoked authority, provider revision, invalid dates and physical ownership after cancellation.

An independent private replay outside the repository verified the pinned DAG blob and all 387 declarations from YAML scalar nodes, preserving the exact numeric-looking token without JavaScript number conversion. Existing historical commit metadata plus newly connector-verified membership for six declared PRs (20 membership rows, stable head/base/count) reproduced 258/387 resolved tasks, 125 no-reference and four unresolved; T reproduced 153/225 with 71 no-reference and one unresolved. All six prefix maxima matched. This is historical fixture evidence, not current production private-repository access or a fresh repository-wide abbreviated-SHA ambiguity audit. No private fixture contents are included in the app or synthetic tests.

The application currently has only a fixed public-repository observer; it has no authorized private GitHub provider or connector-to-app authentication bridge. This follow-up does not configure one. The existing host route remains local-only. Reaching the historical coverage in a live app also requires explicit multi-repository task/reference associations and authoritative lexical handling of numeric-looking declarations. A filesystem grant or project provider label alone cannot authorize the other repository. Production integration remains open pending an approved private read provider or separately authorized historical snapshot import.
