# Task graph contract v1 (T-057 / T-058)

## Scope and adoption

`src/shared/task-graph-contract.ts` specifies the independent graph channel. T-058 adds production normalization, bounded IPC and runtime decoders without increasing current display limits or replacing the graph UI. Date resolution is T-059; layout and interactive UI are later tasks. Synthetic fixture/oracle tests alone are not proof of production completeness; see the evidence categories below. TypeScript types are not a security boundary.

Read from the validated original DAG read model, never from `LiveDagTaskView`, `workspaceTasks`, the 1,000-task display cap, the eight-reference display cap or task pages. Existing application behavior remains unchanged. The 10,000-node source threshold follows the existing index validation bound; it is not a tested interactive performance promise. The additional finite budgets are conservative protocol limits, adjustable only with evidence and a versioned compatibility decision.

## Reader and chunk protocol: T-058 acceptance

1. Resolve project/DAG against current main-owned registration and guard. No renderer-supplied path, command, URL or authority flag. Bind identity to project, DAG, source hash, session generation (workspace + guard + connection) and immutable graph/metadata revision. Validate every request against the current identity, not just an echoed request field.
2. A read returns metadata, or an unavailable reason. A verified empty source is a complete snapshot with zero counts, zero chunks and zero payload bytes. Unread/unavailable source is not empty. A partial snapshot supplies lower-bound known counts, nullable source row total and explicit reasons; never silently label capped data complete. Unsupported input may instead fail closed with `unsupported`.
3. Enumerate unique source nodes and unique directed declaration edges before viewport/group/filter selection. Direction is predecessor -> dependent. Identical tuple `(from ID, to ID, scope)` deduplicates and increments `declarations`; different scope remains distinct. Duplicate IDs are excluded as ambiguous nodes, with incident declarations retained as unresolved endpoints. Duplicate rows must make source coverage partial. External references remain external even if their string matches an internal ID. An incomplete-source missing endpoint is `source-incomplete`, not proven absent. Complete means the declared source was fully enumerated, not that all references resolve.
4. Every chunk has the same contract version and all five identity fields as metadata. Reject mixed revisions, repeated/out-of-range/missing chunk indices, malformed entries, duplicate node/edge identities, invalid endpoint references, mismatched totals and byte counts. Compare serialized UTF-8 bytes, not JavaScript character count. `byteLength` includes the whole serialized chunk, including the field itself (producer computes until its decimal width is stable). Snapshot byte budget is sum of encoded chunk bytes; metadata must also fit one chunk-byte budget. Do not publish an assembled complete snapshot before all expected chunks and aggregate counts pass validation.
5. Apply maximum source nodes/edges, per-chunk nodes/edges/bytes, total bytes, ID/title lengths and deadline. Validate all numeric fields as nonnegative safe integers, indices contiguous from zero, declarations positive. Reject unexpected properties, non-plain records, accessors, arbitrary URLs/source text and unsupported versions at the actual IPC boundary. Recheck counts after deduplication and endpoint resolution. Partial reasons cannot be empty; unknown coverage has null counts; complete reasons must be empty.
6. Cancel source changes, disconnect, workspace/guard changes, permission revocation, unmount/background and explicit cancellation. Stale responses cannot commit UI state; stale source links cannot be opened using an old capability. Retry only a fresh coherent read, never concatenate revisions. Bound producer work and receiver assembly, including requests whose results are abandoned.
7. SCC detection includes singleton self-loops, excludes unresolved endpoints, and is separate from directed group aggregation. Opposing group links are not evidence of a node cycle. Use iterative algorithms for long chains.

## Grouping, projection and partitions

Prefix keys use the existing exact task ID grammar. Unparsed prefix IDs and missing phases have explicit collision-safe keys. Anonymous phases use source index, not title, so equal titles do not merge. Phase index also disambiguates repeated declared phase IDs. Ungrouped places all valid source nodes in one group; it does not discard malformed/duplicate diagnostics.

`GraphProjection` contains bounded visible IDs and independent filter/group annotations, never authoritative adjacency. A node may be both in another group and filtered out. Viewport edge classification considers only resolved node endpoints: both visible = internal; exactly one visible = boundary; neither visible = outside. Thus every unique edge partitions exactly once, including unresolved edges. Unknown references get explanations, never fabricated navigation targets. Group, filter and source-resolution classifications are orthogonal to this viewport partition. Do not use a count of nodes as a count of edges. Group/status aggregates come from the complete index and must retain null/unrecognized declared status vocabulary.

Selection/layout restoration keys include graph project/DAG identity, grouping/group key and layout version. On revision change retain positions only for still-unambiguous IDs; invalidate removed/duplicate selections. Layout positions and viewport state are not part of adjacency truth.

## Linked date provenance: T-059 acceptance

Only explicitly declared commits or commits with verified membership in an explicitly declared PR can contribute. Confirm repository as well as full commit SHA. `LinkedCommitEvidence` carries task/reference, repository, full SHA, committer UTC timestamp, verified URL and linkage mechanism; PR membership has its own revision. The trusted resolver creates evidence, never the renderer. Validate host/scheme/repository, disallow credentials and unexpected ports, and build commit URLs from validated components. Do not accept arbitrary source URLs. SHA ambiguity, repository ambiguity, unsupported declarations and incomplete PR membership remain unresolved.

A reference is resolved only when its full declared resolution is known; a partially fetched PR is unresolved rather than an empty or complete commit list. Resolved references require at least one verified commit. A task is resolved if it has any resolved reference, no-reference only if declaration inspection is complete and there are none (including no unsupported declarations), otherwise unresolved. Task counts form an exclusive partition. Reference counts separately retain unresolved references on otherwise resolved tasks. Reference totals count task-bound declarations (deduplicated within each task); a shared commit in two tasks counts twice, with task provenance preserved.

`resolved` date summary requires every task to have at least one resolved link and every reference resolved. `partial` has a known maximum but incomplete task/reference coverage, including no-reference tasks. `no-reference` means all inspected tasks lack declarations (including a verified empty graph); `unknown` means no known maximum and at least one unresolved/unsupported declaration or incomplete inspection. Do not substitute snapshot commit time, filesystem mtime, author date, PR update/merge time or unrelated repository head time. Null is unknown, never epoch zero.

Choose the greatest verified committer instant; deterministic ties order repository, SHA and task ID, retaining equivalent evidence in the resolver cache. Store UTC, format in Asia/Seoul. Describe as latest confirmed linked commit, never task work/completion time. A formatter must handle year boundaries and multiple years. Cache metadata per source + resolver revision in the authorized read layer; renderer render/hover makes no network or Git calls.

## T-058 production transport implementation

`main/task-graph.ts` normalizes the full admitted `DagReadModel` and owns at most four finite read leases, each lasting ten seconds from metadata request. Active abandoned source operations continue counting against the four-operation limit until physically settled. Every chunk read revalidates the main-owned project mapping, read scope and registered source hash; it never reuses display task/dependency arrays. `main/task-graph-ipc.ts` registers the fixed session/read/chunk/cancel routes under the host's trusted-sender and mutation guards. `renderer/task-graph-client.ts` assembles and validates a single immutable result and rejects superseded reads; later UI owners must invoke its cancel hook on unmount/project changes. Main-side background, disconnect, read-scope invalidation and disposal invalidate leases independently.

Runtime decoders are in `shared/task-graph-transport.ts`. Maximum advertised chunk count is 1,000, checked before assembly allocation. Empty payload chunks are forbidden; a verified empty graph has zero chunks. `idCharacters=256` measures source task IDs, phase IDs and request IDs in JavaScript UTF-16 code units; identity fields have their own 1,024-unit bound, status 128 and titles 2,048. An edge ID is exactly JSON.stringify([fromId,toId,scope]); it is validated against the bounded endpoints rather than incorrectly capped at 256. JSON escaping and UTF-8 byte accounting apply to the full encoded chunk including its byteLength field. Metadata fits the same per-chunk byte budget.

The producer additionally bounds raw dependency declarations at 100,000 before deduplication, limiting work for repeated declarations. Source/query rejection, oversized fields/graphs and unsupported source schemas fail closed rather than advertising a complete capped graph. The existing authoritative query rejects duplicate source IDs; admitted model normalization separately supports duplicate-only partial coverage and diagnostic incident edges, without weakening that upstream source validator. No raw source body, canonical filesystem path, executable or commit-reference list is exported by graph metadata/chunks. The separately bounded selected-task detail endpoint described below exports admitted task declarations only. Commit dates remain a separate provenance-resolver concern.

Validation categories must remain explicit: mocked IPC bus tests exercise the actual preload/registered handlers; pinned-query tests execute the real hash-pinned Python reader on authored synthetic files; neither proves an Electron app launch, graph UI rendering, worker layout, native Mac behavior or real-person usability. Those remain later gates.

Independent-review corrections: the existing source reader's 1,024-unit phase-title and 256-unit phase-ID guards remain unchanged. A non-null phase declaration omitted by that projection sets an explicit main-only phaseProjectionOmissions marker; graph reads reject it as unsupported rather than advertising the normalized null as a complete source declaration. The transport's 2,048-title limit is an upper envelope, not a promise that every upstream format supports that size. Dependency targets must correspond to declared source tasks (resolved or duplicate-ambiguous); external scope applies only to the predecessor. A fabricated missing/external/source-incomplete dependent is rejected even when its bytes/counts are internally consistent.


## Selected-task detail: T-063

`readTaskGraphDetail({requestId, identity, taskId})` reads a single unique task from the same full registered DAG source used by graph metadata/chunks. It never falls back to `LiveDagView.tasks` or `workspaceTasks`, so task 1,001 and references beyond eight remain available. The request accepts only a task ID and the complete five-field graph identity. It cannot nominate a source file, URL, command, grant or arbitrary task object. The dedicated `note-app:graph-detail` route shares the production trusted-sender, reconnect/read-root-mutation and update-cleanup guards.

The service reuses the full reader's mapping/read-grant checks before and after source I/O, recomputes the graph identity, requires an exact identity match and unique task ID, then allowlists that task and the source's policy declarations. The result carries `requestId`, `identity`, `observedAt`, `task` and `policies`; `task` is directly usable by the existing task interpreter with the returned source provenance. It does not claim execution verification. Existing evidence and verification actions still use their own current-source authorization with `identity.sourceHash`.

One result is limited to 512 KiB of serialized UTF-8. Reference lists have at most 10,000 entries; scalar task detail fields have at most 4,096 UTF-16 code units. The admitted reader's 40-entry detail-list bound, malformed-field `details.omissions`, and `commitReferencesUnsupported` remain explicit. A detail result never silently trims these values: unsupported schema/size returns `unavailable`, while successful results have zero *additional display* omissions. Policies are restricted to 200 plain JSON declarations, 20,000 aggregate values and a depth of 32, within the same payload budget. Policies are declarations, never authority to expand access.

Detail operations share the existing four-operation/snapshot capacity and ten-second deadline. Cancelled physical reads keep consuming capacity until they settle. `cancelTaskGraph` cancels the selected detail request; completion releases its lease immediately. Reuse of a request ID cannot allow an old cancelled operation to release a newer one. Runtime invalidation independently cancels reads on scope, generation, background, disconnect and disposal changes.

`parseGraphDetailResult` validates every descriptor, field, bounded array, JSON policy and final byte budget before returning detached data. Consumers must additionally match request ID, task ID and every identity field to the still-current selection, verify the current session, and cancel/discard results after selection changes, close, background or unmount. A stale, unavailable, ambiguous or oversized task must not acquire a detail from a legacy display row.

Tests distinguish service-level adversarial coverage, registered-preload IPC with a synthetic bus, and production-runtime mapping guards. The optional pinned-query integration exercises an authored 1,001-task file through the real configured reader and rejects an on-disk replacement. These do not establish Electron interaction, Mac behavior or real-person usability.
