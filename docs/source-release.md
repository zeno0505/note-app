# Source release procedure

This is a local maintainer tool and review procedure. It does not itself publish source, create tags/releases, upload assets, change a default branch or replace an installed application. No automated publisher or GitHub workflow is included.

## Contract

- Repository: https://github.com/zeno0505/note-app.git
- Feed: https://github.com/zeno0505/note-app/releases/latest/download/note-app-source-update.json
- Asset: note-app-source-update.json, at most 64 KiB
- Tag: source-v<package-version>-build<build-number>
- Exactly nine fields: schemaVersion, channel, repository, version, buildNumber, sourceSha, lockfileSha256, changelog, publishedAt
- Schema/channel: 1/demo

A release must advance source and build number without lowering version. The build must exceed the installed bootstrap build as well as any previous feed build. The planned first-source-release build is 26, subject to checking those actual identities before publication. A local commit is not evidence that its source is publicly available.

## Local generation

Only generate the release manifest after the actual public commit and complete tree have been verified. Work in a clean detached checkout of that exact public commit. Its origin must be the fixed repository, with or without the .git suffix.

The generator derives SHA, version and lockfile digest from committed source. Manual identity flags are rejected. Tracked, staged or untracked changes and hidden index flags fail closed. Ignored dependencies/build output are allowed.

```sh
npm run check
private_parent="$(node --input-type=module -e 'import {mkdtempSync,realpathSync} from "node:fs"; import os from "node:os"; import path from "node:path"; console.log(realpathSync(mkdtempSync(path.join(os.tmpdir(),"note-app-source-release-"))))')"
node scripts/create-source-release.mjs \
  --output "$private_parent/release" \
  --build-number 26 \
  --changelog 'Review and prepare the exact published source update in Settings'
```

The output is a new directory under an existing canonical private parent outside the checkout/Git metadata. It is created with mode 0700; the fixed JSON asset uses 0600 and exclusive creation. Existing or uncertain output is preserved. Changelog lines must be trimmed, 1–500 characters each, with no control characters; use at most 30 repeated flags.

## Reviewed snapshot publication

1. Review every intended source file and its hash. Exclude private configuration, personal data, historical evidence and recovery bundles. Publish only a new clean snapshot branch; do not upload private history or change existing branches implicitly.
2. Obtain approval for the exact public repository, new branch, reviewed file tree and commit strategy. A connector may create different commit metadata and therefore a different SHA. Compare every published path, mode and blob with the reviewed tree; a matching name or file count is insufficient.
3. Fetch the verified actual public commit into a clean isolated checkout and run the checks there. Derive its manifest with the generator; never rewrite a local manifest to pretend it targets a different SHA.
4. Review the exact commit, new tag, version/build, changelog, asset bytes/digest and latest-release effect. Obtain release approval. Publishing latest changes what installed clients discover.
5. Through an already authorized publisher, create an exact-SHA tag and draft release, upload only the JSON, verify asset bytes/digest, then publish as the latest non-prerelease. Never overwrite a tag or asset as an implicit retry.
6. Read back tag identity, release and the fixed feed URL, and compare the downloaded manifest to generated bytes. An uncertain response may mean a remote write succeeded; inspect before retrying.

If no authorized release writer is available, stop at that boundary. Creating credentials or expanding repository/workflow permissions is not implied. Source publication also does not authorize a canonical Mac bootstrap or replacement.

## Tests and limits

The source-release test file contains the 12 top-level generator tests and their eight nested cases. It uses only temporary synthetic local repositories. Tests cover committed identity, detached snapshots, dirty/hidden index rejection, metadata/symlink checks, input bounds and private exclusive output. The six workflow/publisher tests from the maintainer's separate optional publisher are intentionally absent with .github.

Other updater tests remain included. No local test proves a real public release, current remote permissions or native Mac updater acceptance. No packaged application archive is generated by this source-release procedure.
