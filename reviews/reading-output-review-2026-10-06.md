## 실제 출력의 의미와 보정

실제 Orca/공식 DAG query/공개 GitHub를 읽은 main runtime의 네 구역을 검토했다. DAG 선언과 브랜치 커밋은 함께 관측되지만, 작업별 연결이 없어 구현된 기능 목록을 확정하지 못한다. 기존의 DAG 착수 후보 문장만 읽으면 이미 작성된 코드의 재구현 지시처럼 보일 수 있었다. 따라서 다음 문장을 먼저 표시한다.

> 현재 먼저 확인할 일은 DAG의 착수 후보와 기존 코드·검증 기록의 대응입니다. 작업별 연결이 없어 실제 새 구현 순서는 아직 확정할 수 없습니다.

구현 구역에도 “이 DAG 선언을 현재 구현된 기능 목록이나 전체 미구현 판정으로 바꾸지 않습니다”를 표시한다. 착수 후보에는 원문 DAG 기준에서만 후보라는 조건과 기존 코드 확인이 필요하다는 문장을 추가했다. 완료 근거 구역은 작업별 검증 연결과 브랜치 CI 관측을 구별한다. 설계 합의는 현재 구조화된 입력에 없으므로 논의 필요/구현만 남음 둘 다 미확인으로 유지한다. 추가 입력·모델 추론·자동 작업 매핑은 없다.

이는 실제 구현 범위나 설계 합의를 설명하는 완성된 요약은 아니다. 현 입력이 답할 수 있는 범위와 답할 수 없는 범위를 정직하게 설명한다. 코드·검증 대응과 설계 결정의 등록 방법 및 사용자 문장 검수는 남아 있다.

## 공개 근거 대응 초안

아래 ID는 공개 문서가 직접 명시한 연결만 사용한다. 관련 코드가 존재해도 해당 작업의 모든 수용 기준을 충족한다고 추론하지 않는다. 연결을 DAG에 기록하지 않았으며 작업 완료 상태도 바꾸지 않았다.

| T-002 | [환경·측정 프로토콜](../docs/electron-environment-baseline.md), [collector 검증](collector-verification.md), 개발/빌드 스크립트 | Electron 개발 기반과 과거 Linux 일부 측정. 문서는 당시 관측으로 읽어야 하며 최신 Mac 기준으로 일반화할 수 없음 | 현재 Mac 앱 전체 자원/절전 복귀/성능 수용 기준 |

CI 성공은 저장소의 검사 근거이다. 해당 실행의 테스트 항목과 작업 수용 기준을 연결하기 전에는 특정 DAG 작업 완료의 대용으로 쓰지 않는다. 위 초안은 문서·코드 검토이며 앱의 자동 수집 입력으로 추가하지 않았다.

## 창 없는 검증의 한계

실제 자료의 네 구역을 앱의 `ReadingSummary.vue`로 headless SSR하여 문장·제목의 포함 여부를 확인한다. 이는 실제 창의 배치/가독성/사용자 승인 검수가 아니다. 별도 소유 Node runtime에서는 실제 5분 background timer와 수집 시점을 확인할 수 있다. Node CPU/RSS는 Electron main/renderer/GPU 전체 자원 측정이 아니다.

실제 절전 복귀는 Mac의 절전/깨움과 앱 lifecycle을 함께 관측해야 한다. 사용 중인 기기를 재우거나 설정을 바꾸지 않는다. 사용자 작업이 없는 시간의 별도 승인된 창 검증에서 foreground/hidden 각 60초의 앱 전체 metrics, 실제 절전 전후 시점, 네트워크 실패와 단일 복귀 수집 여부를 확인해야 한다. Phase 1 완료로 판정하지 않는다.
